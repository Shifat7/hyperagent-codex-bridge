# v0.5.0 gap analysis and wow-standard

## The wow-standard

The bridge earns a new release only if a skeptical agent builder can clone it and prove, without trusting a screenshot, all of the following:

1. **Safe first contact:** one command verifies Node, Codex, the documented OAuth MCP endpoint, issuer binding, scopes, loopback binding, private state permissions, daily budget, reachable agents, pinned routes, bridge health, and the generated Responses profile.
2. **Zero-credit proof before paid proof:** one command drives the real Codex binary through a complete local shell-tool round trip using a deterministic local relay fixture. It must not use Hyperagent OAuth or credits.
3. **Fail-closed tool semantics:** malformed JSON, invented tools, wrong arguments, and unsupported action types must produce typed failures. They must never become plausible final answers.
4. **Auditable live routing:** every sampling request has a correlation ID, model route, thread receipt, prompt/tool counts, phase timings, total latency, output type, budget position, and explicit cost-data status—without prompt or answer content.
5. **Clean routing:** model aliases pin to immutable agent IDs. Unknown model slugs fail instead of silently falling back. Unrelated named agents are hidden unless discovery is explicitly requested.
6. **Portable regression coverage:** Node 20/22 tests run on Linux, macOS, and Windows; a separate macOS job installs the validated Codex binary and executes the real provider, App Mode, and local-demo tests.
7. **Reproducible handoff:** source, docs, version metadata, test output, security scan, archive, and checksum all describe the same release.
8. **Honest boundary:** a live proof distinguishes measured request count/latency from cost data that the supported MCP surface does not expose.

## What v0.4.1 only claimed or left weak

- The GitHub release body said 20 requests/day while the tag and ZIP enforced six.
- The release ZIP executable code matched the tag, but its documentation did not exactly reproduce the tag and omitted onboarding content.
- GitHub showed no attached release ZIP, checksum, CI log, or App screenshot.
- Plain text and invalid relay actions silently degraded to final answers.
- Unknown model routes could fall back through `defaultAgentId`.
- Audit events lacked request correlation and end-to-end latency.
- “Cost receipt” meant request events plus a manual account observation; the supported MCP result has no per-request usage/cost field.
- `hacb setup` ended with instructions, not an automatic doctor pass.
- There was no one-command, zero-credit proof through the real Codex tool harness.
- The public repository had no CI workflow even though a workflow existed in one distributed archive.
- Smaller relay-model compliance was handled mainly by prompt emphasis, without typed enforcement at the bridge boundary.

## v0.5.0 decisions

- Preserve the supported OAuth MCP architecture; do not call undocumented Hyperagent routes.
- Prefer typed failure over a fluent but unexecuted answer.
- Default to pinned aliases only. Use `hacb models --all` for deliberate discovery.
- Make `hacb demo` a deterministic, real-Codex, no-credit tool-loop proof.
- Require `hacb demo --live --confirm-spend` for a credit-consuming proof.
- Measure request counts and latency; label per-request cost unavailable rather than estimating it.
- Treat Windows as CI parity until a physical Windows/Codex App screenshot is captured.

## Exact remaining blocker

The supported Hyperagent OAuth MCP thread surface does not expose a native Responses inference stream or machine-readable per-request usage/cost. The bridge must create and poll a thread for each Codex sampling request, receive a completed relay answer, and translate it into Responses events. That causes latency, loses true token streaming, and prevents automatic cost attribution.

The platform fix is a documented OAuth-authenticated `POST /v1/responses` endpoint with standard SSE events, client-tool calls, stable trace IDs, and usage/cost metadata.
