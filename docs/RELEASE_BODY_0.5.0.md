# Hyperagent Codex Bridge v0.5.0

Proof, safety, and first-run release.

## Why this release matters

Codex keeps the local filesystem, shell, patches, tests, sandbox, and approvals. Named Hyperagent relay agents provide reasoning through Hyperagent's documented OAuth MCP surface and consume Hyperagent credits.

v0.5.0 upgrades the project from a routing experiment to a bounded, reproducible proof:

- `hacb demo` runs a real Codex local-tool round trip without spending Hyperagent credits;
- `hacb demo --live --confirm-spend` verifies the paid `function_call -> local tool -> final` route;
- strict typed relay parsing rejects invalid JSON, invented tools, and schema-invalid arguments;
- pinned aliases prevent accidental agent/model drift;
- request-correlated receipts measure routing and latency without storing prompts or answers;
- doctor audits OAuth, issuer, scopes, loopback, permissions, budget, routes, bridge, and Codex profile;
- 27/27 tests pass with Codex CLI 0.144.6 enabled;
- CI covers Node 20/22 on Linux, macOS, and Windows, plus a real-Codex macOS job;
- release verification scans for private state, likely secrets, and undocumented Hyperagent routes.


## Security boundary

- Documented `https://hyperagent.com/api/mcp` only.
- OAuth authorization code + PKCE, state validation, issuer binding, and least-privilege thread scopes.
- Loopback-only HTTP on `127.0.0.1` with an independent local bearer.
- Protected local state and reversible Codex App configuration.
- No OAuth tokens, refresh tokens, local bearers, Codex authentication, prompts, or answers in source, archives, or public receipts.

## Limitations

- One Hyperagent thread per Codex sampling request adds latency.
- MCP polling provides keepalives, not true model-token streaming.
- The supported MCP result does not expose per-request usage/cost; exact billing proof still requires an operator-observed account credit delta.
- Typed enforcement detects weak relay-model output but cannot improve the model's reasoning.
- Windows source parity is covered by CI; physical Windows Codex App UI proof remains outstanding.
- This is an adapter, not an official Hyperagent product feature. A native OAuth + SSE `/v1/responses` endpoint should replace it.
